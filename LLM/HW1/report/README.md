# Отчёт: мини-претрейн Qwen3-1B на русской Wikipedia

## Цель и постановка

Модель Qwen3 размером 960 881 664 параметра обучалась с нуля на русской Wikipedia в течение 15 минут на одной NVIDIA A100 80 GB. Цель эксперимента – проверить полный цикл pretrain: токенизацию, подбор основных гиперпараметров, обучение по ограничению wall-clock, анализ loss и первичных генераций.

Все данные и запуски в отдельном каталоге `~/hw1_chagelova`

## Данные и модель

- Dataset: `wikimedia/wikipedia`, конфигурация `20231101.ru`, split `train`.
- Всего: 1 945 063 документа.
- Validation: первые 5000 документов; train: следующие 1 940 063.
- Tokenizer: `ai-forever/rugpt3small_based_on_gpt2`, `pad_token = eos_token`.
- Каждый пример имеет фиксированную длину 512: `truncation=True`, `padding="max_length"`.
- Архитектура: Qwen3, hidden size 2048, 12 слоёв, 16 attention heads, 8 KV heads, MLP 8192.
- Число параметров: 960 881 664.
- Инициализация модели выполнена с нуля.

После токенизации были проверены число строк, наличие 32 parquet-шардов, длина последовательностей и совпадение токенов с исходным датасетом на индексах 0, 4999, 5000 и последнем. Граница train/validation также проверена явно.

## Подбор гиперпараметров

Короткие batch-пробы длились 60 секунд, LR-пробы – 120 секунд. Для них использовалась одна и та же подвыборка из 500 первых validation-примеров. Поэтому probe-loss нужен только для сравнения конфигураций между собой и не равен финальному loss на 5000 примерах.

### Batch size и gradient accumulation


| Конфигурация              | Шаги | Позиции/с | Probe eval_loss | Peak GPU |
| ------------------------- | ---- | --------- | --------------- | -------- |
| bs=8, GA=1                | 238  | 14 902    | 7.6103          | 13.1 GB  |
| bs=16, GA=1, cold compile | 158  | 19 819    | 7.5261          | 16.5 GB  |
| bs=16, GA=1, warm compile | 212  | 26 541    | **7.2014**      | 16.5 GB  |
| bs=16, GA=2, warm compile | 108  | 27 014    | 7.3848          | 18.2 GB  |
| bs=32, GA=1               | 82   | 20 528    | 7.6652          | 27.4 GB  |
| bs=64, GA=1               | 41   | 20 581    | 8.1375          | 49.1 GB  |


`bs=32` и `bs=64` почти не улучшили end-to-end throughput относительно `bs=16`, но дали меньше optimizer updates. При одинаково прогретом compile-cache `bs=16, GA=1` оказался лучше `GA=2`: обработано почти одинаковое число позиций, но loss ниже благодаря вдвое большему числу обновлений. Для финального запуска выбран `per_device_train_batch_size=16`, `gradient_accumulation_steps=1`.

### Learning rate


| Learning rate | Шаги | Позиции/с | Probe eval_loss | Perplexity |
| ------------- | ---- | --------- | --------------- | ---------- |
| 3e-4          | 372  | 24 283    | 7.0372          | 1138.2     |
| 6e-4          | 366  | 23 835    | 6.7183          | 827.4      |
| **1e-3**      | 362  | 23 540    | **6.5882**      | **726.5**  |


Лучшим из проверенных значений стал `learning_rate=1e-3`. Все три запуска оставались численно стабильными.

## Финальная конфигурация


| Параметр                      | Значение                                     |
| ----------------------------- | -------------------------------------------- |
| `per_device_train_batch_size` | 16                                           |
| `gradient_accumulation_steps` | 1                                            |
| `learning_rate`               | 1e-3                                         |
| Scheduler                     | cosine по доле прошедшего wall-clock времени |
| Warmup                        | 100 шагов                                    |
| Optimizer                     | `adamw_torch_fused`                          |
| Weight decay                  | 0.1                                          |
| Adam betas                    | (0.9, 0.95)                                  |
| Precision                     | BF16, TF32 разрешён                          |
| `torch_compile`               | включён                                      |
| Gradient checkpointing        | выключен                                     |
| Seed                          | 42                                           |


Cosine scheduler привязан к wall-clock, а не к длине полной эпохи. Полная эпоха Wikipedia значительно длиннее 15 минут, поэтому обычный epoch-based cosine scheduler почти не успел бы изменить learning rate. `max_steps=100000` используется только как заведомо недостижимый верхний предел; фактическую остановку выполняет `TimeoutCallback` после 900 секунд.

## Итоговые метрики

- Время оптимизации: 900 секунд. Значение `train_seconds=908.2` включает evaluation, запрошенный callback после пересечения лимита.
- Шагов оптимизатора: **3193**.
- Обработано фиксированных token positions: **26 157 056**.
- Средняя пропускная способность: **28 801 позиций/с**.
- Средний train loss за весь запуск: **6.6273**.
- Финальный `eval_loss` на всех 5000 validation-примерах: **5.4807**.
- Финальная perplexity: **240.01**.
- Peak GPU memory: **16.53 GB**.

Полный evaluation и генерации выполнялись уже после остановки оптимизации, поэтому общий `elapsed_sec=952` не означает, что модель обучалась дольше разрешённых 15 минут.

## Графики

Train и validation loss во времени

Train loss быстро снижается примерно с 11 в начале, затем продолжает более медленное снижение до области 6.0–6.4. Validation loss также последовательно уменьшается; устойчивого роста validation loss не наблюдается, то есть за доступные 15 минут переобучение не началось.

## Примеры генераций

Промпт: `Москва — столица`

> Москва — столица в Москве. История. В начале XX века в селе была построена деревянная церковь...

Промпт: `Александр Сергеевич Пушкин родился`

> Александр Сергеевич Пушкин родился в семье рабочего. В 1873 году окончил Московский авиационный институт...

Промпт: `Математика — это`

> Математика — это неорганическое соединение, соль металла и серова. Получение. Сплавление стехиометрических количеств...

Промпт: `Река Волга`

> Река Волга — деревня в составе сельского поселения «Село»... География. Находится на расстоянии примерно 11 километров...

Модель уже воспроизводит локальную структуру русского энциклопедического текста: согласованные фрагменты предложений, заголовки разделов, даты, списки, биографические и географические шаблоны. При этом знания и дальние смысловые связи ещё не сформировались: Пушкину приписывается биография человека XX века, математика описывается как химическое соединение, а Волга – как деревня. Для модели почти в 1B параметров, обучавшейся с нуля только 15 минут, это ожидаемый результат.

## Выводы

1. Loss и perplexity заметно снизились уже за 15 минут: финальный `eval_loss=5.4807`, perplexity около 240.
2. Увеличение batch size выше 16 почти не дало выигрыша end-to-end throughput на этой задаче, но уменьшило число обновлений и ухудшило короткий validation loss.
3. Среди проверенных LR значение `1e-3` показало лучший результат; `3e-4` обучалось слишком медленно для малого временного бюджета.
4. BF16, fused AdamW и `torch_compile` позволили обработать 26.2 млн фиксированных token positions, используя около 16.5 GB GPU memory.
5. Модель научилась локальной форме языка и стилю Wikipedia, но не фактической точности. Для содержательно корректных генераций нужны намного больший объём токенов и время обучения.
